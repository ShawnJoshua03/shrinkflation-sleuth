# Devpost submission draft

**Project name:** Shrinkflation Sleuth
**Tagline:** An AI agent that catches companies quietly shrinking your grocery products
**Track:** Elastic
**Built with:** Google ADK, Gemini 2.0 Flash, Elasticsearch, Elastic MCP Server, Cloud Run, Python

## Inspiration

I spent my internship at Kroger walking grocery aisles, and I kept noticing the same thing shoppers tell researchers they notice: packages getting quietly smaller while the price tag stays put. Shrinkflation has affected roughly a third of grocery items and drove between 3.3% and 10.3% of grocery price inflation from 2019 to 2023 — yet there's no mainstream tool where a shopper can simply ask, "Has my product shrunk?" I built one.

## What it does

Shrinkflation Sleuth is a multi-step agent that investigates shrinkflation on demand. Ask about a product and it searches an Elasticsearch catalog, pulls the size/price history, computes the price-per-unit change (the number shrinkflation hides), cross-checks a database of documented events, and returns a sourced verdict with a severity rating. It also handles brand scorecards, category rankings, shopping-list audits, trend dashboards, and live data discovery — six query types, each a planned multi-tool mission.

## How we built it

The agent is a Google ADK `LlmAgent` running `gemini-2.0-flash`, with six explicit playbooks in its instruction. All data access goes through the official Elastic MCP server — the agent uses all five read-only tools meaningfully: `search` for fuzzy product lookups, `esql` for price-per-unit math and STATS aggregations, `list_indices` and `get_mappings` for dynamic data discovery, `get_shards` for health checks. The dataset (34 products, 170 history records, 29 documented events) was curated from FullCarts, ShrinkWatch, Mouseprint, Capital One Shopping research, and BLS downsizing data, generated by a reproducible pipeline and bulk-indexed into Elastic Cloud. Deployment is two Cloud Run services: the Elastic MCP server in HTTP mode and the agent's FastAPI app.

## Challenges we ran into

Getting genuinely multi-step behavior — not one search call dressed up as an agent — meant writing playbook-style instructions that force the right tool sequences (the product_id from the first search is required by the ES|QL and alert steps). ES|QL syntax is also strict, so the agent retries once with a simplified query before surfacing errors.

## Accomplishments we're proud of

Every one of the five Elastic MCP tools earns its place in a real workflow; the effective-price-increase math turns a vague feeling ("this bag seems smaller") into a number with a source; and the whole stack reproduces from a clean clone in about ten minutes.

## What we learned

ES|QL is a genuinely good fit for agent analytics — one tool call replaces what would otherwise be several aggregation round-trips. And agent quality is mostly instruction quality: precise playbooks beat clever architecture.

## What's next

Live data feeds (Open Food Facts / Open Prices, retailer APIs), user-submitted reports with photo evidence, and price alerts when a tracked product's size changes.
